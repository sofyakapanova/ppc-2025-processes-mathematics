## 1. Введение
Сглаживание изображений с использованием фильтра Гаусса является фундаментальной операцией в области цифровой обработки изображений, компьютерного зрения и машинного обучения. Этот алгоритм представляет собой линейную операцию свертки, где каждый пиксель изображения заменяется взвешенным средним значений его соседей с весами, задаваемыми двумерным гауссовским распределением.  Такая обработка позволяет эффективно уменьшать шум изображения, снижать детализацию.

Цель данной работы - реализовать и проанализировать эффективность MPI-версии алгоритма Гауссова сглаживания изображений, оценить вычислительные преимущества распределенной обработки и определить оптимальные условия применения параллельных вычислений для данной задачи.

## 2. Постановка задачи

### Формальное определение:
Для каждого пикселя выходного изображения B[i][j] вычислить взвешенную сумму значений соседних пикселей входного изображения A:
B[i][j] = ΣΣ A[i+u][j+v] × G(u,v), где G - ядро Гаусса 3×3

### Входные данные:
Бинарный поток, содержащий:
- 2 байта: ширина изображения 
- 2 байта: высота изображения 
- width × height × 3 байт: пиксельные данные в формате RGB (порядок строка-столбец)

 Порядок байтов: little-endian (младший байт первый)

### Выходные данные:
Обработанное изображение в том же формате, что и входное

### Ограничения:
- Фиксированный размер ядра: 3×3 (радиус = 1)
- Значение сигмы: σ = 1.5
- Обработка граничных пикселей: метод clamp (использование ближайшего валидного пикселя)
- Формат: RGB (3 канала на пиксель)

## 3. Базовый алгоритм (Последовательный)

Алгоритм реализует операцию двумерной свертки изображения с ядром Гаусса 3×3. Каждый пиксель выходного изображения вычисляется как взвешенная сумма значений пикселей входного изображения в окрестности 3×3, где веса определяются гауссовской функцией.

Генерация ядра Гаусса
Создается матрица 3×3 весовых коэффициентов, вычисляемых по формуле:
G[u][v] = exp(-(u² + v²)/(2σ²)) / ΣΣ exp(-(u'² + v'²)/(2σ²)), где u,v ∈ [-1, 0, 1]

### Математическая основа:

- Используется гауссова функция с σ = 1.5
- Размер ядра фиксирован: 3×3 пикселя (радиус = 1)
- Ядро симметрично относительно центра

### Процесс создания ядра:

1. Вычисление ненормализованных весов для 9 позиций ядра
2. Суммирование всех полученных весов
3. Нормализация каждого веса для сохранения общей яркости изображения
4. Результат: матрица 3×3, сумма элементов которой равна 1

### Процесс инициализации:
1. Чтение заголовка: Извлечение ширины и высоты из первых 4 байтов
2. Проверка корректности:
   - Подтверждение минимального размера данных
   - Валидация ненулевых размеров изображения
   - Проверка соответствия объема данных заявленным размерам
3. Подготовка буферов:
   - Копирование пиксельных данных во входной буфер
   - Выделение памяти для выходного изображения

### Критические проверки:
- Достаточно ли данных для обработки?
- Корректны ли размеры изображения?
- Соответствует ли объем пиксельных данных заявленным размерам?

### Обработка граничных случаев

Проблема граничных пикселей:
У пикселей на границах изображения нет полного набора соседей 3×3

Используется метод clamp для обработки граничных пикселей
Верхняя и нижняя строки обрабатываются с учетом только доступных соседей

1. Верхняя строка: Использует только текущую и следующую строку
2. Нижняя строка: Использует только текущую и предыдущую строку
3. Левый/правый края: Используют только доступные столбцы
4. Угловые пиксели: Используют только 4 доступных соседа

### Вычислительная сложность. 
Для изображения размером W × H пикселей и ядра фиксированного размера K × K (где K = 3) алгоритм выполняет операцию двумерной свертки. Количество операций на пиксель постоянно и равно K² умножений и K² - 1 сложений для каждого из 3 цветовых каналов. Следовательно, общая временная сложность последовательного алгоритма составляет O(W × H), или O(N), где N — общее количество пикселей.

## 4. Схема распараллеливания
Топология: Мастер-работники

Процесс 0 (Мастер/Master):
- Чтение и валидация входных данных
- Координация всех процессов
- Распределение работы между работниками
- Сбор и объединение результатов
- Формирование итогового изображения

Процессы 1..N (Работники/Workers):
- Получение порции данных от мастера
- Локальная обработка назначенных строк
- Возврат результатов мастеру
- Ожидание следующего задания

### Модель распределения данных
- Изображение разбивается на горизонтальные полосы (строки)
- Каждому процессу-работнику назначается набор строк для обработки
- Для корректного вычисления граничных пикселей каждый работник получает дополнительные строки сверху и снизу (overlap regions)

Мастер отправляет работникам блоки по 2 или 3 строки в зависимости от позиции
- Для первых/последних строк отправляется 2 строки
- Для средних строк отправляется 3 строки (с перекрытием)

### Логика передачи данных:

Для корректного применения фильтра 3×3 каждый обрабатываемый пиксель требует информации о соседях сверху и снизу. Это достигается за счет:

Три типа передаваемых блоков:

1. Блоки для начала изображения (2 строки):
   - Текущая строка для обработки
   - Следующая строка для нижних соседей
2. Блоки для середины изображения (3 строки):
   - Предыдущая строка для верхних соседей
   - Текущая строка для обработки
   - Следующая строка для нижних соседей
3. Блоки для конца изображения (2 строки):
   - Предыдущая строка для верхних соседей
   - Текущая строка для обработки

### Этапы параллельного выполнения:

Фаза инициализации (мастер):
- Чтение и валидация входных данных
- Рассылка ширины изображения всем работникам
- Генерация ядра Гаусса

Фаза распределения работы:
Мастер отправляет работникам блоки по 2 либо 3 строки в зависимости от позиции
- Для блоков из 3 строк: Обрабатывается средняя строка (индекс 1)
- Для блоков из 2 строк:
    Если блок в начале изображения: обрабатывается первая строка (индекс 0) → строка 0
    Если блок в конце изображения: обрабатывается первая строка (индекс 0) → строка H-2 (предпоследняя)
- Результат отправляется обратно мастеру

Фаза завершения:
- Мастер обрабатывает первую и последнюю строки локально
- Рассылка сигнала завершения работникам
- Формирование итогового изображения

### Коммуникационные паттерны

#### Система сообщений с фиксированными тегами

Типы сообщений:

1. Тег 0: Управляющие сигналы (продолжить/завершить работу)
2. Тег 1: Информационные сообщения (ширина изображения)
3. Тег 2: Передача данных изображения (блоки строк)
4. Тег 3: Возврат обработанных результатов

Протокол обмена:

- Все коммуникации инициируются мастер-процессом
- Работники только реагируют на запросы мастера
- Строгая очередность сообщений гарантирует корректность выполнения

#### Динамическое определение размера данных

Использование MPI_Probe:

- Перед получением данных работник проверяет размер ожидаемого сообщения
- Позволяет динамически выделять память под точный объем данных
- Особенно важно для блоков переменного размера (2 или 3 строки)

#### Синхронная модель коммуникаций

Блокирующие операции:

- Все операции отправки и приема являются блокирующими
- Простая и надежная модель управления
- Гарантированный порядок обработки сообщений

### Оценка сложности параллельного алгоритма. 
При распределении строк изображения между P рабочими процессами вычислительная нагрузка на каждый процесс в идеале уменьшается до O(N / P). Однако модель «мастер-работники» вносит существенные накладные расходы:

Коммуникационные издержки: мастер должен отправить каждому работнику блок данных, включающий дополнительные строки (overlap regions). Объём пересылаемых данных растет линейно с увеличением P.
Последовательная часть: обработка первой и последней строк мастером, а также цикл распределения задач создают последовательное «бутылочное горло».
Таким образом, общее время выполнения можно приближённо оценить как T_par ≈ O(N/P) + O(P × C_comm) + O(C_serial), где C_comm — константа, связанная с передачей данных, а C_serial — время выполнения последовательной части. Эта модель объясняет наблюдаемое сублинейное ускорение и падение эффективности при P > 4.

- Последовательная версия: kapanova_s_image_smoothing/seq/
- MPI-версия: kapanova_s_image_smoothing/mpi/
- Общий компонент: kapanova_s_image_smoothing/common/
- Тесты: kapanova_s_image_smoothing/tests/

### Ключевые классы и функции:
- KapanovaSImageSmoothingSEQ - класс последовательной реализации
- KapanovaSImageSmoothingMPI - класс MPI-реализации
- CreateKernel() - генерация ядра Гаусса
- SmoothPixel() - операция свертки для одного пикселя

### Типы данных:
- InType = std::vector<std::vector<uint8_t>> - входные данные
- OutType = std::vector<uint8_t> - выходные данные
- TestType = std::tuple<std::vector<uint8_t>, int, int, std::vector<uint8_t>> - тестовые данные

### Особые случаи обработки:
1. Малое изображение (≤ 2 строк):
   - Обрабатывается полностью мастером
   - MPI-работники не используются

2. Различные соотношения сторон:
   - Высокие узкие изображения: эффективное распараллеливание по строкам
   - Низкие широкие изображения: возможен дисбаланс нагрузки

3. Граничные пиксели:
   - Метод clamp обеспечивает корректную обработку без артефактов
   - Верхняя/нижняя строки обрабатываются мастером отдельно

4. Крайние значения цвета:
   - Поддержка полного диапазона 0-255
   - Автоматическое приведение к uint8_t после вычислений

5. Нестандартные размеры:
   - Проверка корректности размеров в заголовке
   - Валидация объема пиксельных данных

### 7.1 Корректность
Проверка корректности осуществлялась по следующим критериям:
1. Сравнение с эталоном: Результаты MPI-реализации сравнивались с результатами последовательной версии для идентичных входных данных.
2. Инварианты:
   - Сохранение размеров изображения

   - Одноцветные изображения: результат должен совпадать с исходным
   - Изображения с резкими переходами: плавное сглаживание без артефактов
   - Минимальные размеры (2×2, 3×3): корректная обработка
4. Тестирование MPI-специфичных аспектов:
   - Идентичность результатов при разном количестве процессов
   - Корректное завершение при отсутствии работников
   - Обработка сигналов завершения

Результат: Все тесты пройдены успешно, корректность реализации подтверждена.
