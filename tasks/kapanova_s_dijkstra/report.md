## 1. Введение
Алгоритм Дейкстры — один из ключевых алгоритмов теории графов, предназначенный для поиска кратчайших путей от заданной начальной вершины до всех остальных в графе с неотрицательными весами рёбер. 

Цель данной работы - реализовать и проанализировать эффективность MPI-версии алгоритма Дейкстры , оценить вычислительные преимущества распределенной обработки и определить оптимальные условия применения параллельных вычислений для данной задачи.

## 2. Постановка задачи

### Формальное определение:


Для взвешенного ориентированного графа \( G = (V, E) \) с неотрицательными весами рёбер \( w: E \to \mathbb{R}^+ \) и заданной стартовой вершиной \( s \in V \), необходимо найти кратчайшие расстояния \( d(v) \) от \( s \) до каждой вершины \( v \in V \):

\[
d(v) = \min\left\{ \sum_{e \in P} w(e) \mid P \text{ — путь из } s \text{ в } v \right\}
\]


### Входные данные:
Граф представляется в формате CSR (Compressed Sparse Row).
Формат CSR (Compressed Sparse Row) используется для эффективного хранения разреженных графов посредством трёх массивов: row_ptr (указатели на строки), col_idx (индексы смежных вершин) и weights (веса рёбер). Этот формат обеспечивает быстрое итерирование по соседям любой вершины: для вершины i её соседи находятся в диапазоне col_idx[row_ptr[i] ... row_ptr[i+1]-1] с соответствующими весами из weights.

### Структура CSR формата:

1. **row_ptr** — массив указателей на начало списка смежных вершин для каждой вершины:
   - Размер: vertices_count + 1
   - row_ptr[i] — индекс начала рёбер i-й вершины в массивах col_idx и weights
   - row_ptr[i+1] - row_ptr[i] — количество исходящих рёбер из вершины i

2. **col_idx** — массив индексов смежных вершин:
   - Содержит индексы вершин, в которые ведут рёбра
   - Размер: общее количество рёбер в графе

3. **weights** — массив весов соответствующих рёбер:
   - Содержит веса рёбер, соответствующих записям в col_idx
   - Размер: общее количество рёбер в графе

4. **vertices_count** — общее количество вершин в графе
5. **start_node** — индекс стартовой вершины (от 0 до vertices_count-1)

### Выходные данные:
Массив расстояний distances размером vertices_count, где distances[i] содержит кратчайшее расстояние от стартовой вершины до вершины i. Если пути не существует, значение равно std::numeric_limits<double>::infinity().

### Ограничения:
- Граф не содержит рёбер с отрицательными весами
- Разрешены петли (self-loop)
- Граф может быть несвязным
- Индексация вершин начинается с 0

### Критические проверки:
1. Проверка корректности входных данных (vertices_count > 0, start_node в диапазоне)
2. Проверка размеров массивов (row_ptr.size() = vertices_count + 1)
3. Проверка неотрицательности весов рёбер

## 3. Базовый алгоритм (Последовательный)

Последовательная версия алгоритма Дейкстры реализована с использованием приоритетной очереди (кучи) для эффективного выбора вершины с минимальным текущим расстоянием.
Алгоритму Дейкстры необходима очередь с приоритетами для поиска следующего узла для исследования. Узлы добавляются в очередь с приоритетами с указанием их текущего известного общего расстояния — это расстояние служит их «приоритетом». Приоритет узла может быть обновлен с учетом нового общего расстояния, если будет найден более короткий путь к этому узлу. Также необходимо иметь возможность находить и удалять узел с наименьшим общим расстоянием, когда алгоритм Дейкстры определит, что текущее известное общее расстояние узла должно быть его наилучшим возможным общим расстоянием [1]

**Инициализация:**

Создать массив расстояний dist, заполненный бесконечностями
Установить dist[start_node] = 0
Добавить стартовую вершину в приоритетную очередь

**Основной цикл:**

Пока очередь не пуста:
Извлечь вершину u с минимальным расстоянием
Если расстояние до u уже устарело, пропустить
Для каждого соседа v вершины u:
    Вычислить альтернативное расстояние: alt = dist[u] + weight(u, v)
    Если alt < dist[v], обновить dist[v] и добавить v в очередь

## 4. Схема распараллеливания
Параллельная реализация использует итеративную версию алгоритма Дейкстры, где каждый процесс MPI отвечает за обработку определённого подмножества вершин графа. В отличие от классического алгоритма с приоритетной очередью, параллельная версия выполняет синхронные итерации до стабилизации всех расстояний.



### Модель распределения данных

**Распределение вершин:**

Вершины графа равномерно распределяются между процессами
Каждый процесс получает диапазон вершин: [local_first, local_last)
Для каждой вершины в своём диапазоне процесс хранит:
- Информацию об исходящих рёбрах
- Текущее расстояние до вершины

**Обработка граничных случаев**

- Маленькие графы:
При vertices_count < 1000 и proc_count > 2 используется последовательный алгоритм на процессе 0 с последующей рассылкой результатов
- Одноэлементный граф:
Специальная обработка графа с одной вершиной
- Несвязные графы:
Корректная обработка вершин, недостижимых из стартовой

### Алгоритм параллельной версии

1. Инициализация:

- Процесс 0 считывает исходный граф и рассылает общую информацию (количество вершин, индекс стартовой вершины) всем процессам
- Выполняется распределение вершин графа между процессами с использованием блочной декомпозиции
- Каждый процесс загружает информацию об исходящих рёбрах для своих локальных вершин
- Инициализируется массив расстояний: все расстояния устанавливаются в бесконечность, кроме расстояния до стартовой вершины (равно 0)

2. Основной итерационный цикл:

- Выполняется максимум V итераций (где V — количество вершин)
- На каждой итерации:
a. Локальная обработка: каждый процесс обрабатывает свои локальные вершины
b. Глобальная синхронизация: все процессы обмениваются обновлениями расстояний через MPI_Allreduce с операцией MPI_MIN
c. Проверяется, были ли на данной итерации какие-либо изменения расстояний
3. Критерии завершения:

Алгоритм завершается, когда на очередной итерации не произошло ни одного обновления расстояний
Или когда достигнуто максимальное количество итераций (равное количеству вершин)
4. Формирование результата:

После завершения итераций все процессы имеют полный массив расстояний
Процесс 0 собирает или формирует итоговый результат

### Ключевые особенности параллельного алгоритма

- Распределение вершин: Вершины графа равномерно распределяются между процессами. Каждый процесс получает непрерывный диапазон вершин для обработки.
- Синхронизация расстояний: На каждой итерации выполняется глобальная синхронизация через операцию MPI_Allreduce, которая гарантирует, что все процессы имеют одинаковые значения минимальных расстояний.
- Обработка граничных случаев:
a. Для маленьких графов (<1000 вершин) при большом количестве процессов автоматически переключается на последовательный алгоритм
b. Специальная обработка начальной вершины: только процесс, содержащий стартовую вершину, инициализирует её расстояние в 0
- Оптимизация коммуникаций: Используется минимально необходимый объём данных для обмена — только массив расстояний, а не информация о структуре графа.
